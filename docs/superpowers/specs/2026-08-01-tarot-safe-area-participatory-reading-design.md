# 塔罗灵感牌安全区、导航与参与式解读设计

日期：2026-08-01

## 目标

在不改变离线优先、本地隐私和现有 78 张牌数据兼容性的前提下，以 `C:\Users\27363\Desktop\tlp\` 的 12 张界面稿为视觉基线，统一应用的页面外壳、安全区、导航、抽牌参与流程和离线解读质量。

本轮必须解决：

- 顶部月亮图标无交互、二级页面无法逐层返回。
- 首页、底部导航和固定操作侵入系统安全区或相互遮挡。
- 底部导航项目过多，记录入口与右上角更多按钮职责不清。
- 首页问候固定为晚上好。
- 抽牌完成后直接显示结果，用户缺少参与感。
- 离线解读知识维度不足，容易与具体问题连接不紧密。
- 页面颜色、间距、圆角和视觉层级不够统一。

## 产品边界

- 所有核心抽牌、牌库、解读、记录、收藏、笔记和设置保持离线可用。
- 不增加登录、广告、会员、付费入口、网络依赖或无关权限。
- 不需要生成视频或在线音乐。使用 ArkUI 原生动画、现有牌面和牌背即可满足参与感，并保持视觉与离线约束一致。
- 解读用于娱乐与自我反思，不给出确定性的医疗、法律、投资或命运判断。
- `tlp` 仅作为只读参考素材目录，不修改项目范围外文件。

## 页面外壳与导航

### 页面层级

应用保持单个 Stage 页面入口，但用明确的强类型页面标识和页面历史栈管理内部视图。一级页面为首页、占卜、牌库和我的；二级视图包括输入问题、选择牌阵、静心洗牌、选牌、翻牌、结果、牌义详情、灵感记录、设置子页和关于应用。

返回操作必须弹出历史栈的上一层，不再把所有返回都写死为首页。切换底部一级导航时重置当前二级栈，避免跨栏目返回到无关流程。系统返回事件与标题栏返回按钮调用同一套返回逻辑。

### 首页退出

首页左上角显示 48vp 的返回按钮。第一次点击进入短暂的“再次返回”状态并显示轻提示；在 1.5 秒内第二次点击时显示原生确认对话框。只有用户在对话框中确认后才终止当前 Ability；取消后保持首页。超时后再次点击按第一次处理。

### 更多菜单

右上角三点按钮仅负责打开或关闭锚定菜单，不直接切换页面。菜单至少包含“灵感记录”，点击该菜单项后才进入记录页。菜单点击区域不小于 48vp，点击菜单外区域、执行返回或切换底部栏目时关闭菜单。

### 底部导航

底部固定四项：

1. 首页
2. 占卜
3. 牌库
4. 我的

底部导航只在四个一级页面显示。占卜流程、结果、牌义详情、记录和设置子页隐藏底栏，让页面获得完整可用高度。记录不再作为底部导航项。

## 安全区与响应式布局

应用使用统一页面外壳管理状态栏、手势导航区和内容最大宽度。外壳读取系统避让区域，并分别约束标题栏、滚动内容、底部导航和固定操作区：

- 标题栏位于顶部安全区之后，不与状态栏或挖孔区域重叠。
- 页面背景可延伸至系统区域，但交互控件和正文不可进入避让区域。
- 底部导航位于系统手势区之上，并包含真实底部安全间距。
- 二级页面的固定操作按钮位于底部安全区之上；滚动内容增加等量尾部间距，最后一项可以完整滚动到按钮上方。
- 无固定底栏的滚动页仍保留系统底部避让间距。
- phone 使用全宽布局；tablet 和宽屏使用居中最大宽度容器，不拉伸牌面和正文。
- 文本不使用固定高度容器。字体放大和横屏时允许自然换行、滚动或网格降列，不发生文本截断和控件重叠。

## 视觉系统

`tlp` 浅色稿作为本轮唯一界面基线。整体采用雾白背景、深靛主文本、灰紫次文本、紫罗兰主操作色、极淡紫面板和少量暖金边线。禁止各页面自行声明颜色和尺寸。

新增或整理设计令牌：页面背景、表面层、强调层、主次文本、边框、激活色、危险色、阴影、内容边距、标题栏高度、底栏高度、按钮高度、圆角和最大内容宽度。卡片圆角控制在 8vp 以内，只有牌面或设计稿明确要求的主视觉容器可以使用更大的圆角。

标题栏统一为 48vp 左右点击区域、居中标题和右侧更多按钮。图标使用 ArkUI 可用的系统符号或已有字符资源，并提供无障碍说明。所有触控目标至少 48vp。

## 分时问候

问候语由纯函数根据本地设备小时生成，便于单元测试：

- 05:00-08:59：早上好
- 09:00-11:59：上午好
- 12:00-13:59：中午好
- 14:00-17:59：下午好
- 18:00-21:59：晚上好
- 22:00-04:59：夜深了

每个时段配一条简短、克制的支持语，不使用确定性预言。页面出现和从后台恢复时刷新问候，设备时间变化后无需重启应用。

## 参与式占卜流程

完整流程为：输入问题 -> 选择牌阵 -> 静心洗牌 -> 逐张选牌 -> 确认选择 -> 逐张翻牌 -> 完整解读。

### 输入与牌阵

用户输入问题，并选择问题场景、解读深度和可选心情。问题分类同时使用用户场景选择和文本语义；明显冲突时以文本语义为主，并保留用户选择作为语气上下文。牌阵继续支持单牌、三张时间流、关系洞察和七张进阶。

### 洗牌

进入静心页时不预先显示结果。用户通过点击牌堆或水平滑动完成三次洗牌，每次触发轻量的层叠位移、旋转与进度反馈。音效和振动只在相应设置开启时触发。洗牌未完成前不可进入选牌。

### 选牌与翻牌

洗牌完成后展示可滚动或扇形排列的牌背候选。用户按牌阵所需数量逐张选择，已选牌抬起并显示对应位置标签。选择可在确认前撤销；选满后点击“确认选择”锁定结果。

牌面按牌阵顺序逐张翻开。每次由用户点击当前牌或“翻开下一张”触发；全部翻开后才生成和展示完整解读。每日一抽也必须经过洗牌、选择、确认和翻牌，不再从首页直接显示结果。

澄清牌最多三张且不与主牌或既有澄清牌重复。每张澄清牌同样经过选择、确认和翻开，追加到当前记录时保持同一记录 ID。

## 解读与知识库

### 知识模型

保留 78 张牌及现有稳定 ID，为每张正逆位知识增加以下离线维度：

- 成长视角：这张牌可利用的力量和可能的调整方向。
- 六类场景解读：学业、事业、关系、社交、个人成长和日常状态。
- 常见模式：牌意在行为、边界、沟通、节奏或资源上的表现。
- 可执行建议：具体、低风险、当天或近期可观察的小步骤。
- 反思问题：与场景和牌阵位置一致的开放式问题。

知识字段必须 78 张完整、正逆位完整、六场景完整，并继续标注来源。扩展内容是基于公共领域牌义的原创中文整理，不复制未授权文本。

### 问题相关性

离线问题分析提取：场景、关注对象、时间倾向、核心主题和用户真正关切。生成解读时按以下信息组合，而不是仅拼接通用牌义：

1. 用户原问题和文本分类结果。
2. 用户选择的场景、心情与解读深度。
3. 每张牌的正逆位、牌阵位置和对应场景知识。
4. 多牌之间的强化、张力、转折和发展路径。
5. 近期主题设置开启时的本地历史主题。

输出结构为：与问题的连接、可利用的力量、需要留意的盲点、牌阵联系、下一步行动和反思问题。单牌省略不适用的牌阵联系段落。

### 建设性乐观主义与安全

语言强调选择空间、可调整因素和可执行行动，不把逆位等同于坏结果，也不把困难强行美化。不得保证复合、录取、升职、获利、康复或其他结果。

医疗、法律、投资、自伤等高风险问题继续通过 `SafetyService` 软化：保留与情绪和自我反思相关的内容，明确塔罗不能代替专业判断，并给出合适的现实支持方向。安全提示不能被“乐观语气”覆盖。

## 架构边界

- `pages/` 负责页面编排和页面局部状态，不直接访问 Preferences。
- `components/` 承担页面外壳、标题栏、底部导航、更多菜单、牌堆和翻牌等可复用 UI。
- `services/` 承担页面历史、问候、问题分析、抽牌状态机和解读生成。
- `repositories/` 继续作为本地持久化唯一入口。
- `models/` 定义强类型页面、抽牌阶段、选牌状态和扩展知识模型。
- `common/` 集中设计令牌、资源映射和纯工具。
- 所有用户可见文本进入字符串资源。

## 错误与恢复

- 本地数据初始化失败时显示现有存储错误提示，不阻断不依赖历史的抽牌流程。
- 洗牌、选择和翻牌只操作内存状态；用户返回上一步时按页面栈恢复已输入问题和已选牌阵。
- 从选牌页返回洗牌页会清空尚未确认的选牌；已确认后返回必须先提示会丢弃当前结果。
- 保存失败时保留当前结果和记录 ID，允许重试，不重复创建记录。
- 更多菜单、退出确认和破坏性数据操作均使用明确的可取消状态。

## 测试与验收

业务行为测试先行，至少覆盖：

- 六个问候时段及 00:00、05:00、09:00、12:00、14:00、18:00、22:00 边界。
- 页面历史入栈、逐层返回、一级导航重置和首页双击返回判定。
- 三点按钮只开菜单，记录只通过菜单项进入。
- 洗牌三次门槛、选牌数量、撤销、确认锁定、逐张翻牌和澄清牌去重。
- 文本场景与手选场景冲突时的问题相关性。
- 正逆位均保持建设性但不保证结果。
- 不同场景和不同问题不落入同一固定模板。
- 多牌强化、张力、转折和位置联系。
- 高风险问题的安全软化与专业支持提示。
- 78 张牌、正逆位和六场景知识完整性。

完成后执行：

1. `scripts/check-standard.ps1`
2. 牌库与主题资源校验
3. ArkTS/Hypium 测试构建与设备端测试（设备可用时）
4. debug HAP 与 ohosTest HAP 构建
5. phone 关键流程截图与安全区观察
6. tablet、横屏和字体放大设备观察（对应设备可用时）

只有实际观察到的设备结果可以写入 `design-qa.md`；构建成功不能描述为真机或模拟器通过。

## 完成标准

- 两张用户指出的问题图和 `tlp` 全流程在布局层级、颜色、间距、牌面比例和导航关系上保持一致。
- 所有页面可预测地返回上一层，主页双击返回后才出现退出确认。
- 四栏导航和更多菜单职责清晰，记录不出现在底栏。
- 顶部状态栏、挖孔、底部手势区、底栏、固定按钮和滚动正文无重叠。
- 问候随本地时间变化。
- 用户完成洗牌、选牌、确认和逐张翻牌后才看到解读。
- 解读明确回应用户问题，保持建设性乐观，同时遵守风险边界。
- 静态门禁、数据校验、测试和构建全部通过；缺失的设备维度明确标记为 `blocked`。
