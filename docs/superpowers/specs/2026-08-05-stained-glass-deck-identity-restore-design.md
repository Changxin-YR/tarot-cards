# 第二套鎏金牌面与应用标识还原设计

## 目标

把用户提供的第二套鎏金塔罗图导入“鎏星穹庭”，使其与现有“月影花庭”一样具备 78 张可映射牌面和 1 张牌背；同时恢复应用原始名称“塔罗灵感牌”和原始图标。

## 方案选择

1. 推荐：从 16 张横向牌面源图精确切出 78 张正面与 1 张牌背，转换为 600×1000 优化 JPEG，恢复原始名称和图标。它不改变稳定牌号、离线流程或 UI 结构，包体增加可预测且可校验。
2. 复用第一套牌面填补第二主题。实现最快，但设置页主题切换没有真实视觉差异，不能交付第二套素材。
3. 在运行时解码原始 PNG。避免离线预处理，但会把约 50 MiB 源图带入安装包，加载性能、包体和上传请求体都更差。

本次采用方案 1。

## 数据与资源

- 将每张源图按从左到右五个画格拆分；`271b98ba-caa8-4261-b583-b5ba825aa127 (1).png` 的第五格作为牌背，其余 78 格映射至标准大阿卡纳、权杖、圣杯、宝剑和星币 ID。
- 输出统一为 `entry/src/main/resources/base/media/stained_glass_*.jpg`，尺寸固定为 600×1000。源图只用于本地生成，不纳入工程资源和 HAP。
- 导入操作使用临时目录，完整性、可读性、尺寸、重复牌和单套资源总大小均通过后才替换输出，避免半套资源。
- JPEG 使用优化压缩并以每套 16 MiB 为上限，避免因为将原始 PNG 编入包体或传输请求而扩大到可能被网关拒绝的大小。应用自身不添加网络上传。

## 标识还原

- `AppScope/resources/base/element/string.json` 与 `entry/src/main/resources/base/element/string.json` 的应用名称恢复为“塔罗灵感牌”。
- `AppScope/resources/base/media/app_icon.png` 和 `entry/src/main/resources/base/media/app_icon.png` 恢复至当前分支 `HEAD` 的原始内容。
- 不回退当前“灵感卡片”描述性文案，不改包名、权限、签名、业务模型、路由或存储格式。

## 验证

- 先让资源导入测试因缺少完整的第二套映射而失败，再实现映射和生成逻辑并验证通过。
- 执行导入器、主题资源单测、标准脚本、差异空白检查及 debug/ohosTest HAP 构建。
- 本轮不做设备安装或视觉结论，因此不修改 `design-qa.md`。
