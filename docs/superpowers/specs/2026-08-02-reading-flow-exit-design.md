# 占卜流程统一退出入口设计

## 目标

在占卜流程的所有阶段提供一致、可发现的退出入口，让用户能够一步结束当前牌局并返回首页。这里的“退出”只退出本次占卜流程，不终止应用。

## 范围

- 覆盖问题填写、牌阵选择、洗牌、选牌、翻牌和单牌/多牌结果页面。
- 牌库、牌义详情、记录、设置等普通浏览页面不增加该入口。
- 结果页继续保留澄清牌、保存和再次抽牌操作，退出按钮位于现有操作组最下方。

## 交互与视觉

- 使用用户选择的文字按钮方案：透明背景、紫色文字、48vp 固定点击高度，不使用警示色。
- 按钮显示“退出”，无论页面内容长度如何均位于该页面主要内容或操作组之后，并保留底部安全区。
- 点击后立即返回首页，不显示确认框；返回首页后无法通过系统返回键恢复旧牌局。
- 按钮提供无障碍文字，点击区域不小于 48vp。

## 实现边界

- 页面通过一个公共 `@Builder` 渲染退出按钮，避免重复视觉定义。
- 退出行为由单一方法完成：重置抽牌服务与临时状态，并调用根导航选择逻辑将导航栈替换为首页。
- 清理范围包括问题、心情、场景、深度、牌阵、候选牌、选择牌、待翻牌、主牌、澄清牌、澄清解读、结果文本、保存状态和当前记录 ID。
- 已保存的历史记录、收藏、牌义笔记、设置与主题不受影响。
- 不新增网络、权限或持久化写入。

## 测试与验收

- 先新增失败测试，断言结束占卜后导航栈只包含首页，并且新的牌局状态对象回到初始值。
- 静态布局测试断言所有占卜页面都调用公共退出按钮，结果页按钮位于“再抽一次”之后。
- 执行标准门禁、牌库校验、debug HAP、ohosTest HAP 与 API 22 设备端 Hypium。
- 设备验收只记录实际观察结果，重点检查长结果页底部按钮、系统手势区避让和返回首页行为。
