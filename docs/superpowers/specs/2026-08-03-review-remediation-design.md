# 审查问题核验与上架整改设计

## 目标

以代码、项目既有设计和可验证的平台配置语义为依据，核验第三方审查提出的问题。修复真实缺陷，补齐离线应用内能够落地的上架材料与合规交互，不机械实施会破坏 API 兼容性、导航行为或现有视觉基线的建议。

本轮完成后，应用继续满足以下边界：核心功能完全离线；不新增登录、广告、付费、联网权限或无关权限；用户问题、心情、笔记、记录和收藏仅保存在本机；所有解读继续定位为娱乐、自我反思和情绪整理。

## 审查结论处置

| 审查项 | 结论 | 处置 |
| --- | --- | --- |
| `GOLD` 实际为紫色 | 命名缺陷属实，直接改成金色会破坏现有紫色主操作基线 | 将主操作令牌改名为 `PRIMARY` 系列，新增独立 `ACCENT_GOLD` 系列；紫色用于按钮和选中态，金色仅用于牌框、主题标记等点缀 |
| UI 硬编码中文 | 属实 | 将洗牌进度、已选数量、每日位置、澄清位置和候选牌序号等 UI 文本迁入字符串资源；领域数据文件中的中文牌义不作为 i18n 资源迁移对象 |
| 页面切换无动效 | 属实 | 导航切换使用 180-220ms 淡入和轻微位移；不延长洗牌、翻牌或保存操作 |
| tablet 仅有限宽 | 部分属实 | 保留 phone/tablet 声明和 720vp 内容上限；按可用窗口宽度动态调整候选牌与牌库列数，避免平板三列过宽；本轮不强行把全部页面改成双栏 |
| `onBackPress` 始终返回 `true` | 不是缺陷 | 项目使用自有导航栈、逐层返回和根页面双击退出，必须消费返回事件；保留现有行为并补回归测试 |
| `DrawService` 未使用变量 | 属实 | 删除 `drawThree` 中未使用的副本变量 |
| 空 `catch` | 属实 | 使用统一日志记录模块、操作和错误类型；不得记录用户输入或历史内容；已有用户可见错误状态保持不变 |
| `InterpretationService.requireCard` 导致历史打开崩溃 | 报告所述路径不成立 | 历史页直接读取已保存结果，不调用 `build`；现有卡牌查找也有回退。`requireCard` 对新抽牌数据继续 fail-fast，不增加掩盖错误的宽泛捕获 |
| `Index.ets` 单体过大 | 维护性问题属实，整文件重写风险过高 | 本轮提取新增合规 UI、公共 Header 和底部导航等低耦合区域；业务流程状态仍由 `Index` 编排，后续按页面继续拆分 |
| 心情 `ForEach` 无稳定 key | 属实 | 使用心情选项的稳定字符串标识作为 key |
| 隐私政策与协议入口 | 应用内能力不足属实 | 增加首次确认、独立隐私政策页、独立用户协议页和设置页入口；生成外部发布文案及 AppGallery 配置清单 |
| `compatibleSdkVersion` 与目标版本相同 | 审查解释错误 | `compatibleSdkVersion` 是最低兼容基线，不是精确版本锁定；项目使用 API 22 能力，保留 6.0.2(22)，不降到未经审计的 API 12 |
| Splash 缺失 | 不准确 | 已配置系统启动窗口、图标和背景；保留即时启动，不新增人为延迟的独立 Splash |
| 深色模式缺失 | 可选增强，不是本轮上架缺陷 | 本轮不引入完整双主题系统，避免扩大视觉与设备验证范围 |
| `launchType` 未显式声明 | 配置清晰度问题 | 显式声明 `singleton`，保持默认运行语义不变 |
| 签名、隐私 URL、年龄分级 | 仓库外发布操作 | 在 `docs/release/` 记录 AppGallery Connect 待办；不写入签名秘密，不虚构外部 URL，不把人工操作标记为代码已完成 |

## 视觉与响应式设计

### 颜色语义

- `PRIMARY`：现有紫色 `#6757E8`，用于主要按钮、选中态和重点交互。
- `ACCENT_GOLD`：使用现有暖金视觉基线，用于牌框、主题标记和少量强调。
- `TEXT_ON_PRIMARY`：主按钮上的白色文字。
- 迁移全部旧 `GOLD`、`GOLD_LIGHT` 和 `TEXT_ON_GOLD` 调用，删除误导性名称。
- `color.json` 与 ArkTS 令牌保持一致，不保留未使用的旧深色主题颜色冒充当前主题。

### 响应式布局

- 页面继续居中并限制最大宽度，防止宽屏阅读行过长。
- 新增纯函数根据可用宽度返回网格列数；phone 使用紧凑列数，较宽窗口增加列数。
- 候选牌、牌库和其他固定比例牌面使用稳定 `aspectRatio`、列间距和最大尺寸，动态内容不得改变网格几何。
- 监听窗口尺寸变化并更新布局；注册和注销窗口监听应成对出现。
- tablet 与横屏最终效果必须以实际设备或模拟器观察为准；没有观察结果时仅记录构建与测试事实。

### 页面过渡

- 所有内部页面切换统一经过导航辅助方法，避免各处直接赋值产生不一致动画。
- 切换时使用短时淡入和轻微纵向位移；退出抽牌流程、保存和删除等命令不增加动画等待。
- 系统返回键继续调用同一导航栈，避免手势返回与按钮返回产生不同页面历史。

## 合规流程

### 首次确认

- 应用初始化本地数据后检查已接受的协议版本。
- 未接受当前版本时显示全屏 `ComplianceGate`，主应用内容不可交互。
- 用户可分别打开隐私政策和用户协议全文。
- “同意并继续”持久化当前版本后进入主应用；“不同意并退出”调用 Ability 退出。
- 协议版本更新后再次展示确认。持久化失败时不得假装已同意，应保留确认页并展示通用错误。

### 政策内容

- 明确应用完全离线、不注册、不联网、不收集或上传个人信息。
- 说明问题、心情、笔记、历史和收藏保存在当前设备，卸载或清除本地数据后的后果。
- 说明塔罗内容仅供娱乐、自我反思与情绪整理，不构成医疗、心理、法律或投资建议，也不承诺预测结果。
- 设置页永久提供政策与协议入口。
- `docs/release/` 中的 Markdown 文案作为外部托管来源；实际 HTTPS URL、签名和年龄分级由发布者在 AppGallery Connect 完成。

### 内容安全

- 扩充高风险问题覆盖，包含紧急健康、自伤伤害、法律裁判和具体投资决策等表达。
- 命中高风险表达时只给出反思性提示和寻求专业帮助建议，不生成确定性结论。
- 日志不得包含命中的原始问题文本。

## 架构与文件职责

- `entry/src/main/ets/common/DesignTokens.ets`：准确的视觉令牌语义。
- `entry/src/main/ets/common/AppLogger.ets`：脱敏 `hilog` 封装。
- `entry/src/main/ets/common/ResponsiveLayout.ets`：宽度到列数的纯函数映射。
- `entry/src/main/ets/services/ComplianceService.ets`：当前协议版本与确认判断。
- `entry/src/main/ets/repositories/LocalAppStore.ets`：协议版本的 Preferences 读写。
- `entry/src/main/ets/services/AppDataService.ets`：向页面提供合规状态操作，不允许页面直接访问 Preferences。
- `entry/src/main/ets/components/ComplianceGate.ets`：首次确认和政策阅读 UI，通过回调调用服务。
- `entry/src/main/ets/components/AppHeader.ets`：公共顶部区域。
- `entry/src/main/ets/components/BottomNavigation.ets`：公共底部导航。
- `entry/src/main/ets/pages/Index.ets`：页面和业务流程编排，不承载新的持久化细节。
- `entry/src/main/resources/base/element/`：所有新增可见文本和颜色资源。
- `entry/src/main/module.json5`：显式 `singleton`，其他 SDK 和设备配置保持不变。
- `docs/release/`：隐私政策、用户协议和发布人工检查清单。

## 错误处理与隐私

- `AppLogger` 只接受固定模块、固定操作、错误对象，不提供自由拼接用户数据的接口。
- `EntryAbility.loadContent` 失败、窗口配置失败、本地存储失败和退出失败均记录错误。
- 可恢复存储错误继续通过现有 `storageError` 告知用户；窗口安全区读取失败继续使用设计令牌回退值。
- 合规版本写入失败必须阻止进入主应用。
- 不向 `design-qa.md` 写入未观察的 tablet、横屏、深色模式或上架审核结论。

## 测试与验证

业务行为遵循测试先行：

1. 为 `ComplianceService` 编写当前版本、旧版本、空版本和保存失败测试。
2. 为 `ResponsiveLayout` 编写 phone、边界宽度和 tablet 列数测试。
3. 扩展安全服务测试，覆盖新增高风险表达和普通反思问题。
4. 新增静态回归脚本，检查字符串资源引用、稳定 key、无空 `catch`、日志脱敏接口、响应式网格、过渡入口、`launchType` 和 SDK 基线未被误改。
5. 保留导航测试，验证逐层返回、根页面双击退出和根 Tab 重置。
6. 执行 `scripts/check-standard.ps1`、debug HAP 构建与 `entry@ohosTest` HAP 构建。

设备观察属于独立步骤。只有实际在对应 phone/tablet 或横屏环境中观察到的结果，才写入 `design-qa.md`。

## 非目标与外部阻塞

- 不实现网络隐私政策托管，不新增 `INTERNET` 权限。
- 不配置或提交 release 签名、证书、口令或密钥。
- 不代替发布者填写 AppGallery Connect 年龄分级、隐私 URL 或提审说明。
- 不承诺含“塔罗”题材的应用一定通过人工审核；只通过产品定位、免责声明和安全处理降低风险。
- 不在本轮完成所有页面的组件化重写或完整深色主题。
