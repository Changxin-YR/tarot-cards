# 《塔罗灵感牌》V1.0 设计规格

## 1. 目标与边界

《塔罗灵感牌》是一款 HarmonyOS Stage 模型原生应用，使用 ArkTS 与 ArkUI 开发。应用通过塔罗牌帮助用户整理情绪、反思处境并形成下一步行动，不提供确定性预测。

核心体验必须离线可用：

- 单牌、三牌阵、每日灵感、牌库、收藏、笔记、历史记录和设置均不依赖网络。
- 用户问题、心情、笔记、抽牌结果和历史记录只保存在本机。
- 不登录、不投放广告、不设置付费入口。
- 小艺智能体是用户主动开启的可选增强能力；不可用、未配置或断网时，自动回退到本地解读，不阻断核心流程。

## 2. 方案比较与结论

### 方案 A：纯离线模板

只使用固定牌义和少量模板组合。实现简单、隐私边界最清晰，但个性化程度有限，三牌组合容易重复。

### 方案 B：离线结构化解读 + 可选小艺增强

本机根据问题类别、问题文本、心情、牌位、正逆位、近期主题和牌义知识生成结构化结果；用户可主动请求小艺进行进一步对话。核心功能不依赖小艺。

### 方案 C：小艺优先

将主要解读交给在线智能体，本地只提供兜底。个性化自然语言更强，但违反原报告的离线优先、无网络依赖与数据不外传边界。

采用方案 B。它在隐私、离线可用性和个性化之间最平衡，并保留 HarmonyOS 智能化体验。

## 3. 页面与导航

应用使用四个底部入口：

1. 首页
2. 抽牌
3. 牌库
4. 记录

设置位于首页右上角。页面包括：

- 启动页
- 三屏首次使用说明
- 首页
- 抽牌方式选择
- 问题输入
- 洗牌与抽牌
- 单牌结果
- 三牌阵结果
- 每日灵感
- 牌库列表
- 牌库详情
- 历史记录
- 记录详情
- 收藏
- 设置
- 隐私说明
- 关于应用

从首页到抽牌结果最多经过“选择方式 → 输入或跳过问题 → 抽牌”三步。

## 4. 视觉系统

以用户提供的 UI 总览和组件设计图为验收基准：

- 深蓝星夜背景：`#0E1024`
- 次级背景：`#141B3A`
- 卡片背景：`#1F2854`
- 深紫强调：`#2E3870`
- 紫色辅助：`#4C3F7A`、`#6B5A9A`、`#8A79B7`
- 金色层级：`#C9A46A`、`#E2C07A`、`#F2D89A`、`#FFF1CC`
- 主要文字：米白色
- 装饰元素：月亮、星轨、金色细线、轻柔光晕

视觉还原顺序为：安全区与页面骨架、标题与导航、主卡片、内容节奏、按钮层级、装饰细节。所有颜色、间距、圆角、字重和动画时长放入设计令牌，不在页面中重复硬编码。

现有六张牌组图鉴只作为视觉参考，不能直接切图作为 78 张独立牌。应用优先使用压缩包中的 78 张独立公共领域 RWS 图片作为可运行素材；若后续提供与效果图一致的独立牌素材，保持文件 ID 不变即可无损替换。

## 5. 知识库与简体中文化

第一批知识来源：

- `cards.json`：78 张牌的繁体中文牌名、正逆位关键词和象征。
- `tarot-lite.md`：牌义速查、单牌/三牌/每日灵感的输出结构。
- `skill/tarot/SKILL.md`：安全、语气、模式和组合规则。
- A. E. Waite 的公共领域著作《The Pictorial Key to the Tarot》(1910)，作为来源锚点。

忽略与应用知识无关的 Claude 安装教学。

转换要求：

- 全部用户可见文本使用简体中文和简体标点习惯。
- 统一牌名：大阿尔克那 22 张；权杖、圣杯、宝剑、星币各 14 张。
- 保留英文辅助名、来源、授权、原始关键词与规范化关键词。
- 每张牌至少包含正位/逆位关键词、基础含义、象征、情感、工作学习、自我成长、行动建议种子和反思问题种子。
- 知识数据使用稳定 ID，图片资源名与 ID 一一对应。
- 构建期检查 78 张数量、ID 唯一性、牌名唯一性、图片存在性和字段完整性。

## 6. 个性化解读

### 6.1 输入

本地解读只使用用户明确提供或应用已经本地记录的内容：

- 当前问题文本
- 问题类别：关系、工作学习、选择决策、情绪压力、自我成长、日常
- 当前心情
- 抽到的牌
- 正位或逆位
- 牌阵位置
- 用户自愿启用的近期历史主题

不默认建立生日、星座、性别、职业等长期个人画像。

### 6.2 生成流程

1. 规范化用户问题并进行安全分类。
2. 匹配问题类别和主题关键词。
3. 读取当前牌位对应的牌义、象征和建议种子。
4. 根据正逆位和牌阵位置选择不同表达。
5. 三牌阵先生成单牌分段，再计算共同元素、张力、递进与互补关系。
6. 将用户心情和当前问题映射到解释句，不臆造未提供的事实。
7. 输出“简短启发 → 深度解读 → 可执行建议 → 反思问题”。
8. 通过安全过滤器去除宿命论、恐吓、诊断和确定性结论。

同一输入在同一算法版本下应可复现；文案允许有限的本地候选句轮换，但不得改变核心含义。

### 6.3 安全边界

医疗、法律、投资、死亡、疾病或其他高风险问题只提供情绪整理方向，并清楚提示咨询相应专业人士。逆位不等于坏结果。解读不使用“注定、一定、保证、必然”等确定性措辞。

## 7. 小艺增强

Agent Framework Kit 仅用于应用内主动拉起已在小艺开放平台配置的智能体。入口位于结果页“小艺继续聊”，并满足：

- 默认不自动调用。
- 调用前说明将离开完全离线模式。
- 只在用户主动确认后传递当前问题、抽牌结果和本地解读摘要。
- 不传递历史记录、笔记或其他本地数据，除非用户在当次操作中明确选择。
- Kit 不可用、智能体未配置、系统版本不支持或网络不可用时，保留本地结果并给出平静的降级提示。
- 调试配置与正式智能体标识分离，不在源码中提交密钥或敏感配置。

## 8. 数据与模块边界

### 页面层

只负责编排、状态展示、导航和用户事件，不直接访问数据库或实现抽牌、解读规则。

### 组件层

包含页面框架、标题栏、底部导航、牌面卡片、结果分段、心情选择、空状态、确认弹窗和设置项。

### 服务层

- `TarotCatalogService`：加载并缓存 78 张牌。
- `DrawService`：单牌、三牌、每日固定结果和正逆位。
- `InterpretationService`：本地个性化解读。
- `SafetyService`：问题分类与内容安全。
- `HistoryService`：记录、收藏和笔记编排。
- `SettingsService`：首启、音效、振动、逆位和自动保存。
- `XiaoYiAgentService`：能力检测、用户确认、拉起和降级。
- `AudioService`、`HapticService`：独立管理系统反馈。

### 持久化层

使用 Preferences 保存轻量设置，关系型数据库保存历史、牌卡笔记和收藏。所有写入通过 Repository；记录包含稳定 ID、创建/更新时间和 schema 版本。

## 9. 状态与异常

- 抽牌结果在动画开始前计算，动画只负责展示。
- 动画期间禁用重复点击。
- 应用进入后台时暂停动画和音效，返回后恢复到安全状态，不在后台生成结果。
- 图片缺失时显示统一占位图。
- 牌库数据损坏时回退内置最小数据并提供恢复入口。
- 保存失败时保留当前结果和输入，允许重试。
- 小艺失败不影响本地结果。

## 10. 工程与测试

工程采用 Stage 模型、ArkTS、ArkUI，按 `pages/components/services/repositories/models/common/resources` 分层。

验证至少包括：

- 静态标准门禁。
- Hvigor debug 构建。
- 78 张牌数据完整性测试。
- 单牌不越界、三牌不重复、每日牌同日固定测试。
- 正逆位设置测试。
- 问题分类、个性化映射和安全过滤测试。
- 设置、历史、收藏和笔记持久化测试。
- 离线模式和小艺不可用降级测试。
- 小屏、长中文、字体放大、深色对比度与无障碍说明测试。

没有真实设备证据时，只声明编译和静态验证通过，不把模拟结果写成真机结果。

## 11. 验收标准

- 工程可在本机 DevEco/Hvigor 环境构建。
- 78 张牌及其简体中文资料完整、稳定、可搜索。
- 单牌、三牌、每日灵感完整可用且离线运行。
- 解读确实结合问题、类别、心情、牌位和正逆位，不只是复述固定牌义。
- 历史、收藏、笔记和设置重启后仍存在。
- 小艺为明确的可选增强，失败时无功能损失。
- 核心页面视觉层级、配色、圆角、间距和组件状态与参考图一致。
- 应用不包含广告、付费、登录或无关权限。
