# 塔罗布局与满幅牌面修正设计

## 背景

当前 phone 设备截图暴露出五类相关问题：顶部三点菜单展开后推动首页正文；底部应用导航、目录内容与系统手势区重叠；部分牌面左右存在深色或浅色留边且显得窄长；牌阵选择页纵向节奏松散；页面显示侧边滚动条。

本轮只修正布局、牌面生成与对应验证，不改变离线抽牌、解读、记录、收藏、设置或持久化行为。

## 已确认根因

1. `Header()` 在菜单展开时把高度从 `HEADER_HEIGHT` 增加到 `HEADER_HEIGHT + 60`，菜单因此参与父级布局并推动后续内容。
2. 根内容容器同时使用 `height('100%')` 和顶部/底部 padding，沉浸式窗口下存在总高度超出可用区域的风险；安全区只在窗口初始化时读取一次，首次返回零值后没有刷新。
3. `CatalogPage()` 外层没有占用父级剩余高度，内部 `Grid` 与底部导航之间缺少稳定的布局边界。
4. `prepare_theme_assets.py` 使用 contain 策略把窄裁片等比放入 `400x600` 背景画布，左右留边已经写入 JPEG；ArkUI 的 `ImageFit.Cover` 无法去除资源内部留边。
5. `Scroll`、`Grid` 等容器没有统一显式关闭滚动条。

## 方案

### 根布局与安全区

- 保持沉浸式窗口和现有 avoid-area API。
- 根 `Stack` 内使用一个固定 `100%` 高度的纵向布局；顶部和底部安全区改为布局内部的明确占位，不再作为 `100%` 容器的外部 padding。
- 页面显示时再次刷新 avoid area。底部系统上报为零时使用一个保守的最小手势区占位；系统上报更大值时以系统值为准。
- 内容区占据安全区之间的剩余高度，底部导航始终是内容区最后一个固定高度子节点。
- `CatalogPage()` 外层显式 `layoutWeight(1)`，目录网格只能在导航上方的剩余区域滚动。

### 顶部菜单

- `Header()` 始终保持 `HEADER_HEIGHT`，只负责标题和按钮。
- “灵感记录”菜单移到根 `Stack` 中，作为位于 `safeTop + HEADER_HEIGHT` 下方、右侧对齐内容边距的浮层。
- 浮层使用固定宽度、白色表面、细边框、轻阴影和高 `zIndex`；展开或关闭不会改变任何页面尺寸。
- 三点按钮、系统返回和菜单项导航继续复用现有 `menuOpen` 与强类型导航逻辑。

### 牌面资源与展示

- 保留现有图鉴裁片坐标、两套主题、资源名和 `400x600` 输出契约。
- 生成时将每个已定位的牌面裁片直接校正到 `400x600`，不再创建背景画布或粘贴等比缩略图。该校正用于恢复图鉴中窄视角牌面的统一 `2:3` 牌形，并消除写入资源的左右色带。
- 牌背采用同一满幅输出边界；所有运行时 Image 继续使用 `2:3` 稳定尺寸和 `ImageFit.Cover`，不额外横向拉伸或 UI 级缩放。
- 目录、详情、翻牌、结果和记录页继续引用同一强类型媒体映射，因此资源修正自动覆盖全部牌面入口。

### 牌阵页与滚动

- 牌阵页保留四个选项和既有文案，收紧标题说明与卡片之间的间距，卡片使用一致的中等圆角和更紧凑的高度/内边距。
- phone 上首屏应完整呈现四个牌阵；tablet 继续受 `CONTENT_MAX_WIDTH` 限制。
- 所有纵向、横向 `Scroll`、`Grid` 和需要滚动的列表显式设置 `scrollBar(BarState.Off)`；滚动能力保持不变。

## ArkTS 与 ArkUI 约束

- `@Builder` 内不声明普通临时变量。
- 只使用项目现有 API 22 可编译的 `Stack`、`Column`、`Scroll`、`Grid`、`layoutWeight`、`margin`、`position/align` 和 `scrollBar` 声明式属性。
- 新增数字均进入 `DesignTokens` 或 float 资源；用户可见文本继续使用字符串资源。
- 不在页面中加入牌面处理逻辑；图像校正只发生在离线资源生成脚本中。

## 验证

1. 先增加可重复的布局/资源门禁，使当前实现因动态 Header 高度、未关闭滚动条、目录页高度边界和牌面侧边留色而失败。
2. 修改源码和资源脚本后重新运行门禁，确认两套主题各 78 张牌和牌背均为 `400x600`，且不再包含生成器添加的左右背景带。
3. 执行 `check-standard.ps1`、主题资源校验、ArkTS 类型检查、debug HAP 与 `entry@ohosTest` HAP 构建。
4. 若当前 API 22 模拟器可用，安装并实际观察：首页菜单覆盖而不位移、牌库底部无重叠、牌面满幅、牌阵页四项完整、页面无可见滚动条。
5. 只有本轮真实观察到的设备结果才写入 `design-qa.md`；无法运行的设备配置保持 `blocked`。

## 非目标

- 不修改牌义、抽牌概率、解读算法、记录结构或用户数据。
- 不新增网络、登录、广告、付费、小艺依赖或权限。
- 不改变两套主题名称、牌库数量、牌 ID 或媒体资源映射接口。
