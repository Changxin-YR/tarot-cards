# 音效混音与柔化设计

## 目标

消除洗牌、选牌和翻牌音效几乎每次都出现约一秒延迟的问题，同时将现有点击声替换为更轻柔、与塔罗翻阅相称的短音；修正首页底部导航四项图标因不同 Unicode 字形边界而显得大小不一的问题。所有反馈继续离线运行，且不改变用户的音效、振动设置或抽牌状态机。

## 已确认的原因

`NativeReadingFeedbackPort` 已在应用出现时预加载 `reading_feedback.wav`，资源在 `loadComplete` 后才允许播放，且 wav 的有效采样从 0 ms 开始。因此，资源加载、文件前置静音和 UI 事件排队均不能解释每次点击约一秒的延迟。

当前 SoundPool 的 renderer usage 为 `STREAM_USAGE_GAME`。本机 API 24 SDK 的 SoundPool 声明说明，只有 `STREAM_USAGE_UNKNOWN`、`STREAM_USAGE_MUSIC`、`STREAM_USAGE_MOVIE` 和 `STREAM_USAGE_AUDIOBOOK` 会在播放短声音时使用混音模式。频繁延迟与当前不走该混音路径的配置相符。

## 方案

### 播放链路

- 保留已解码、双路并发的 `media.SoundPool`，不改为 `AudioRenderer` 或 `AVPlayer`。
- 将 `audioRenderInfo.usage` 从 `STREAM_USAGE_GAME` 改为 `STREAM_USAGE_MUSIC`，使短音效走 SDK 明确说明的混音播放路径，避免每次点击重复承担音频焦点或路由建立成本。
- 删除零音量 warm-up 播放及其常量。它不能让每次播放稳定进入混音路径，且 0 音量不应作为硬件通道已就绪的证据。
- 继续在 `loadComplete` 后公开可播放的 soundId；音频初始化或播放失败仍只写入脱敏日志并跳过当次声音，绝不阻断抽牌流程，也不补播过期点击。
- 保持 `MAX_CONCURRENT_STREAMS = 2` 和原有的洗牌、选牌、翻牌调用位置，以支持短时间连续点击。

### 音色资源

`reading_feedback.wav` 更新为离线打包的单声道 48 kHz、16-bit PCM WAV，目标时长 90-110 ms。声音由低幅度的两层柔和泛音构成，带 4 ms 平滑起音和完整衰减，不使用硬切的瞬态点击；峰值保持克制，避免在安静环境中突兀。资源首个有效样本必须位于 5 ms 内，避免把声学起音延迟重新写回文件。

同一资源继续用于三个反馈事件。三种事件的差别仍由已有轻量振动时长表达，不增加新的用户可见文字、权限、网络访问或持久化数据。

### 底部导航图标

截图显示首页选中图标的背景直接承载在 `Text` 字形框上，而首页、抽取、卡片库和我的使用了实际边界不同的 Unicode 字符。相同的 `fontSize` 不能使它们在视觉上等大，且选中态会放大这一差异。

`BottomNavigation` 将把图标字形放入共享的 36vp 方形承载区，并在其中水平和垂直居中。为消除 Unicode 字符本身的轮廓差异，字号集中为首页/抽取 22vp、卡片库 21vp、我的 19vp；选中态只改变该固定尺寸承载区的底色和字色，未选中态保留同尺寸的透明承载区。`NAV_ICON_HEIGHT` 同步为 36vp，标签轨道、64vp 导航栏高度、48vp 以上点击区域、四个路由和文本资源均保持不变。

## 备选方案与取舍

- 持续运行 `AudioRenderer`：可以完全接管流式输出，但需要维护缓冲区、生命周期和空数据策略。SDK 明确不建议持续发送静音数据，复杂度与功耗风险都不适合一个短音效。
- 继续叠加静音或低音量预热：无法解释和解决每次播放的延迟，且无法证明输出通道已被实际唤醒，因此不采用。

## 测试与验收

1. 在 `scripts/test_appgallery_followup.py` 先增加会失败的回归：SoundPool 必须使用 `STREAM_USAGE_MUSIC`、不存在 warm-up 零音量播放，并保留就绪检查、双路并发和立即播放调用。
2. 在同一专项脚本中检查 wav 的格式、时长、起声位置与峰值范围，防止重新引入延迟、刺耳瞬态或不兼容的资源参数。
3. 保留 Hypium 中已有的开关分流、加载完成与反馈事件测试；新逻辑不在 UI 中写入播放实现。
4. 在同一专项脚本中断言底部导航的图标承载区使用共享方形设计令牌、居中承载字形，且选中和未选中状态不改变承载尺寸。
5. 依次运行专项回归、`scripts/check-standard.ps1`、debug HAP 和 `entry@ohosTest` HAP 构建。
6. 真实设备人工执行洗牌、选牌和翻牌各至少十次，确认声音不再有约一秒滞后且音色轻柔。设备前不得在 `design-qa.md` 中声明该听感结论。

## 范围边界

仅修改声音服务、离线 wav 资源、底部导航图标承载布局、相应回归和任务/变更记录。不会变更页面布局以外的视觉层级、抽牌逻辑、设置数据结构、权限、联网行为或小艺功能。
