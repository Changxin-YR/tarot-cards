# 双主题牌面全量替换与离线解读 V3 设计

## 背景

当前应用已经具备两套各 78 张的主题资源和离线解读 V2，但牌面与用户提供的新素材不一致，部分展示区域存在比例不协调、黑边和拉伸感。现有解读虽然能结合问题场景、正逆位和近期主题，表达仍偏模板化；澄清牌还会被直接拼入主牌数组重新解读，结果页主要展示牌图，没有说明澄清焦点及其对原解读的作用。

本轮使用 `C:\Users\27363\Desktop\tlp\` 中的两种完整视觉风格替换现有牌面，并将解读升级为完全离线、结构化、可测试的 V3。

## 已确认决策

- 月影花庭使用玫瑰粉金牌面。
- 星璃穹顶使用紫黑金牌面。
- 两套各包含 78 张唯一正面牌，套内和跨套均不得出现相同图片。
- 解读同时增强问题匹配、多牌联系、正逆位内容和澄清牌解释，并保持简洁易读。
- 不引入网络、登录、广告、会员、付费入口或在线 AI。

## 目标与非目标

### 目标

- 从用户素材中建立可重复生成、可追溯的两套 78 张牌面资源。
- 全应用使用一致的牌面比例，消除拉伸、拼图间隔、两侧黑边和明显外框。
- 为 78 张牌补充足够的正逆位结构化语义，使结果真正回应用户问题。
- 深化多牌之间的转折、呼应和张力分析。
- 为每张澄清牌生成独立的焦点、释义、影响和行动提示。
- 保持旧记录、收藏、笔记和设置可读取。

### 非目标

- 不提供确定性的医疗、法律、投资或命运判断。
- 不以网络模型作为核心或降级依赖。
- 不改变抽牌随机规则、牌阵数量或最多三张澄清牌的产品限制。
- 不迁移或重写用户已经保存的旧解读文本。

## 牌面资源设计

### 素材拆分与映射

导入流程先从原始横向五牌和 2x5 拼图中裁出全部候选牌格，再生成联系表进行人工视觉复核。依据牌面可见标题、编号和标准塔罗顺序，将候选牌映射到 22 张大阿卡纳及权杖、圣杯、宝剑、星币各 14 张。每种风格中多出的封面、牌背或附加图不计入 78 张正面牌。

导入清单记录以下信息：

- 主题 ID 与牌 ID。
- 来源文件相对路径及文件校验值。
- 行列位置和最终裁切坐标。
- 输出资源名、像素尺寸和输出校验值。

资源生成必须由脚本根据清单完成，使同一输入可重复得到相同输出。脚本不得修改素材目录中的原文件。

### 裁切与展示

- 裁切到实际牌面边缘，去除拼图间隔、黑边和非牌面留白。
- 保持素材真实宽高比，不进行非等比缩放。
- 同一套输出统一像素尺寸和编码格式，两套使用相同的展示宽高比。
- ArkUI 图片组件统一复用牌面尺寸令牌；牌库、选牌、翻牌、结果和记录详情不得各自硬编码冲突比例。
- 正面不增加明显边框；只保留与现有界面一致的轻微圆角和必要阴影。
- phone 根据可用宽度稳定排布，tablet 对内容设置最大宽度，动态内容不得改变牌格尺寸。

### 资源门禁

自动校验必须覆盖：

- 每套恰好 78 张正面和一个合法牌背。
- 牌 ID 分布为大阿卡纳 22 张、四组小阿卡纳各 14 张。
- 文件非空、可解码、尺寸一致且资源名符合 HarmonyOS 规范。
- 所有 `TarotThemeMedia` 引用真实存在，无遗漏和占位图回退。
- 通过精确哈希与感知哈希检查套内重复和跨套相同图片。
- 通过边缘像素检查发现成片纯黑边；检测结果需结合联系表人工复核，避免把正常深色画面误判为黑边。

## 离线解读 V3

### 数据结构

保留现有 `TarotCard` 的牌名、牌组、元素、象征、关键词和基础含义，在正逆位语义中补充可利用力量、潜在阻碍、行动种子和反思种子。场景知识继续由服务层维护，页面不承载解释规则。

`ReadingContext` 明确区分主牌与澄清牌。`ReadingResult` 保留摘要、逐牌解读、牌间联系、行动、反思和安全提示，并增加可选的结构化澄清解读集合。

每条澄清解读至少包含：

- 牌 ID、牌名、正逆位和序号。
- 澄清焦点。
- 结合原问题的牌面释义。
- 对主解读的影响类型与说明。
- 可执行的下一步提示。

### 生成流程

1. 识别问题属于事业推进、学习压力、关系沟通、选择权衡、情绪照顾、自我成长或日常主题。
2. 提取用户问题中的具体关注点；用户问题为空时使用所选场景的中性焦点。
3. 结合牌阵位置、牌的正逆位语义和场景视角生成逐牌解读。
4. 多牌阵分析牌序变化、正逆位转折、大阿卡纳占比、同花色聚集及元素呼应，生成联系段落。
5. 结合心情和近期主题补充个性化信息，但不让它们覆盖当前问题。
6. 使用问题文本、牌 ID、正逆位和牌阵位置形成稳定选择键，从候选表达中确定性取值；相同输入应得到相同结果。
7. 统一去重、限制长度并经过安全软化，移除确定性承诺。

简洁模式保留核心结论、短逐牌解释、联系、一个行动和一个反思问题。深入模式可以增加原因与牌间关系，但不得重复逐牌段落。

### 多牌联系

多牌联系不再只连接第一张与最后一张关键词。引擎按以下顺序选择最有信息量的关系：

- 正位到逆位或逆位到正位形成的状态转折。
- 相邻牌在牌阵位置上的推进、阻碍或修正关系。
- 大阿卡纳集中体现的长期主题与小阿卡纳体现的现实落点。
- 同花色重复带来的主题加强。
- 元素之间的支持、制衡或节奏差异。

未形成可靠关系时使用中性整合表达，不编造因果关系。

## 澄清牌设计

### 生成原则

主牌和澄清牌分开传入解读服务。加入澄清牌时保留主解读结构，以附加方式解释新信息，不把“澄清 1”等位置混入普通牌阵联系。

第一张澄清牌优先回应主解读中最明显的张力、阻碍或尚未落地的行动。第二、第三张除回应仍未解决的焦点外，还说明与前一张澄清牌是强化、补充、提醒还是调整关系。

每张澄清牌输出：

- `澄清焦点`：说明它正在澄清哪一处问题。
- `牌面释义`：结合正逆位、用户问题和场景解释牌义。
- `对原解读的影响`：明确属于强化、补充、提醒或调整。
- `下一步提示`：提供一个现实、可执行且非确定性的方向。

### 结果页呈现

结果页在主解读之后提供独立的“澄清解读”区域。每张澄清牌展示牌图、牌名、正逆位、焦点、释义、影响和下一步提示。布局使用普通页面内容带，不嵌套多层卡片；长文本自然换行，不改变牌图比例。

用户每新增一张澄清牌，页面更新澄清区域和必要的行动提示，不改变主牌数量。已保存的当前记录再次保存时更新同一记录 ID，不产生重复记录。

## 持久化与兼容

- 新记录保存结构化澄清解读和算法版本 `3`。
- 本地编码格式增加新版本标识，解码器继续兼容现有 V1、V2 和 V3 记录。
- 旧记录没有结构化澄清解读时，从已保存的澄清牌和当前牌库提供基础牌义展示；不得修改旧摘要或静默覆盖原记录。
- 解码失败继续向上层传播，不能用空集合覆盖本地数据。
- 页面仍通过服务层与仓库交互，不直接读写 Preferences。

## 测试策略

业务行为遵循测试先行：

- 资源导入测试先验证裁切数量、映射、尺寸、黑边和重复检测，再生成正式资源。
- 解读测试覆盖具体问题匹配、不同场景差异、正逆位建设性表达、稳定输出、简洁/深入长度与禁止承诺词。
- 多牌测试覆盖正逆位转折、同花色聚集、大阿卡纳集中和无可靠关系的降级表达。
- 澄清牌测试覆盖主牌数量不变、每张字段完整、连续澄清之间的关系、最多三张及会话内不重复。
- 编解码测试覆盖新版往返、旧版记录兼容、损坏数据拒绝和已保存记录追加澄清后原 ID 更新。
- UI 静态门禁检查统一牌面比例、无明显边框、资源映射和结果页澄清区域。

完成后执行标准静态门禁、牌库与主题资源校验、Hypium、debug HAP 和 `entry@ohosTest` HAP 构建。设备观察使用 API 22 phone 模拟器，覆盖主题切换、牌库、选牌、翻牌、结果、连续澄清和记录回看。只有实际观察到的结果写入 `design-qa.md`；未测试的 tablet、横屏或字体放大场景继续标记为受限验收。

## 成功标准

- 两套主题各显示 78 张对应风格的唯一牌面，主题切换后所有页面一致更新。
- 牌面在应用中无可见拼图黑边、无非等比拉伸、无明显外框。
- 解读明确回应用户问题，正逆位内容有区别，多牌联系不再只是首尾关键词拼接。
- 每张澄清牌都说明澄清对象、牌义、对原解读的影响和下一步。
- 新旧记录均可读取，现有本地数据不因升级丢失。
- 静态门禁、资源校验、测试和 HarmonyOS 构建全部通过。
