# 《塔罗灵感牌》第二轮设计规格

## 1. 基线与优先级

本规格是第二轮开发的唯一设计基线，覆盖并取代以下旧结论：

- 不再沿用深色星夜主界面，改为参考图中的浅色月光紫罗兰界面。
- 不再限制为单一牌面主题，正式支持“月影花庭”和“星璃穹顶”两套完整主题。
- 不把小艺作为占卜流程的一部分；核心解读、追问和记录全部离线完成。
- 不再沿用一次点击直接生成结果的简化页面，改为五步式占卜流程。
- `docs/superpowers/plans/2026-07-30-reference-draw-flow-upgrade.md` 仅保留为历史记录，不作为实现依据。

发生冲突时，执行优先级为：本规格 > 用户提供的第二轮修改文档 > 现有 V1 规格 > 早期视频分析计划。

## 2. 产品边界

- HarmonyOS Stage 模型，ArkTS + ArkUI，目标 API 24。
- 所有核心功能离线可用，不申请网络、相机、麦克风、位置、通讯录、账号或媒体库权限。
- 不包含登录、会员、充值、次数限制、广告和付费解锁。
- 用户问题、场景、牌组、解读、笔记、收藏与设置仅保存在本机。
- 塔罗内容用于娱乐和自我反思，不输出确定性医疗、法律、投资或命运判断。

### 3.2 设计语言

- 页面背景：低饱和月光白与极浅紫，不使用深色整页背景。
- 主色：`#6757E8`；深色文字：`#25205F`；次级文字：`#716D91`。
- 卡片背景：高不透明白色；浅紫背景：`#EEEAFE`；金色点缀：`#D8B978`。
- 主标题使用中文衬线气质，正文使用系统可读字体；字体缺失时保证排版稳定。
- 页面装饰使用星轨、月亮、微光和少量金色星点，但正文区域保持清晰。
- 普通卡片圆角 20vp，主视觉卡片 28vp，按钮 24vp 或全圆角。
- 间距只使用 4/8/12/16/24/32vp 体系。
- 每页最多一个主操作按钮；阴影和发光统一且克制。

### 3.3 “100% 还原”的工程定义

在 941×1672 参考比例下，还原页面信息层级、相对尺寸、间距、圆角、颜色、按钮位置和核心素材构图。实际设备必须响应安全区、字体缩放和横竖屏，禁止用整张截图冒充界面，因此不同屏幕允许产生必要的响应式差异。

## 4. 信息架构

底部导航统一为五项，所有页面保持一致：

1. 首页
2. 占卜
3. 牌库
4. 记录
5. 我的

“牌阵选择”是占卜流程内部步骤，不在部分页面显示为独立底部入口。“笔记”归入牌库详情和记录详情，不替换“记录”入口。

## 5. 五步占卜流程

1. 写下问题：最多 300 字，可选择学习、事业、情感、人际、自我成长、今日指引；可选择简洁或深入解读。
2. 选择牌阵：单张指引、三张时间流、关系洞察、七张高级牌阵，全部免费。
3. 洗牌与抽牌：随机抽牌或从牌库选择；洗牌动画约 1 秒，翻牌 300–500ms。
4. 逐张确认：按牌阵位置选择并翻牌，同一次会话不得重复，结果快照在刷新和前后台切换后保持稳定。
5. 占卜结果：展示牌面、位置、正逆位、关键词、核心提示、行动建议和注意事项。

返回上一步保留问题、场景、解读方式和牌阵选择。动画中屏蔽重复点击；进入后台立即停止视觉动画，但不重新随机。

## 6. 牌阵定义

- 单张指引：`核心提示`。
- 三张时间流：`过去`、`现在`、`未来趋势`。
- 关系洞察：`我的状态`、`对方或外部状态`、`关系核心`。
- 七张高级牌阵：`当前状态`、`问题根源`、`已知资源`、`隐藏影响`、`当前阻碍`、`行动建议`、`发展趋势`。

用户点击整张牌阵卡选择；选中状态包含紫色描边、选中图标和轻微发光。主按钮固定在内容底部，并随页面滚动保持可达。

## 7. 两套正式牌面主题

### 7.1 主题标识

- `moon_garden`：月影花庭。来源为附件图 19（大阿尔卡那）、18/24（权杖与圣杯）、20（宝剑与星币）。
- `stained_glass`：星璃穹顶。来源为附件图 21（大阿尔卡那）、22/25（权杖与圣杯）、23（宝剑与星币）。

每套必须包含 78 张正面牌和至少 1 张牌背。主题切换免费、离线，不改变卡牌稳定 ID、牌义、历史数据和抽牌概率。

### 7.2 受控导入

用户已确认两套图鉴是正式素材来源，因此允许在项目的离线资源准备阶段拆分，但必须经过以下流程，不能把整张图鉴直接交给运行时：

1. 从每套三张图鉴提取 22 + 28 + 28 张牌面及牌背。
2. 统一裁切为 2:3 可视区域，保留完整牌框，不拉伸。
3. 统一命名为 `<theme>_<stable_card_id>.webp`。
4. 逐张校验编号、花色、中文名、英文名、边框、重复图和明显生成缺陷。
5. 对存在错误的内嵌文字，不依赖图片文字作为业务真值；牌库和结果页由 ArkUI 额外渲染标准名称和正逆位。
6. 任一主题未通过 78 张完整性校验时，不在设置中显示为可选主题。

最终资源使用 `base/media` 的扁平、唯一名称，避免依赖不稳定的动态 rawfile 路径。主题到资源的映射由生成脚本产出并由构建期校验。

## 8. 牌库与主题切换

- 牌库支持全部、大阿尔卡那、权杖、圣杯、宝剑、星币分类。
- 搜索中文名、英文名、关键词、花色、正位和逆位含义。
- 牌库网格采用三列 phone 布局；tablet 增加列数但限制最大内容宽度。
- “我的 > 牌面主题”展示两套主题的预览、完整性状态和当前选中状态。
- 主题切换后，首页、洗牌页、牌库、结果页和历史详情立即使用新主题；历史记录保留当时的 `themeId`，回看时优先使用原主题。

## 9. 本地解读与继续追问

解读输入为：用户问题、用户选择场景、解读方式、牌阵位置、卡牌、正逆位和本地牌义。输出固定为：

1. 核心提示
2. 行动建议
3. 注意事项

深入解读增加牌间联系和位置递进，但仍只使用本地结构化模板。继续追问保留原牌组和上下文，每次增加一张澄清牌，最多三张；不调用网络或小艺。

## 10. 本地数据

- Preferences：当前主题、默认牌阵、默认解读方式、逆位、今日牌策略、动画、音效、触感和字体设置。
- 结构化记录仓库：记录 ID、创建时间、问题、场景、解读方式、牌阵、牌 ID、正逆位、位置、结果、主题 ID、备注、收藏状态和澄清牌。
- 页面不得直接访问 Preferences 或数据库，统一通过 Repository/Service/ViewModel。
- 删除单条、清空记录和清空全部数据必须二次确认。

## 11. ArkTS 与 ArkUI 约束

- 明确类型，不使用 `any`、动态对象或魔法字符串状态。
- `@Builder` 内不声明普通临时变量，不执行数据库、解析或随机逻辑。
- 页面只做布局、事件和状态展示；随机、牌阵、解读、主题映射与持久化位于独立模块。
- 所有用户可见文本进入字符串资源；所有视觉值进入设计令牌或资源。
- 列表使用稳定唯一 key；固定牌面和按钮使用稳定尺寸，动态内容不得导致布局跳动。
- 所有图标按钮提供文字或无障碍说明，点击区域至少 48vp。
- phone 与 tablet 共用功能，tablet 内容最大宽度 720vp。

## 12. 测试与验收

### 自动验证

- 两套主题分别为 78 张且稳定 ID 完整、无重复、图片可读。
- 牌阵抽牌数正确且同次不重复；关闭逆位后全部正位。
- 主题切换不改变卡牌业务 ID，历史回看使用保存的主题 ID。
- 问题、场景、解读方式和抽牌快照在返回及前后台切换后保持。
- 澄清牌最多三张且不与当前会话牌重复。
- 本地解读不出现确定性、高风险结论。
- 静态门禁、Hypium 测试 HAP 和 debug HAP 构建通过。

### 设备验证

- 按附件图 12–17 逐页比较安全区、排版、间距、圆角、卡面比例、按钮和底部导航。
- 验证两套主题切换、五步流程、1.3× 字体、小屏滚动、tablet 最大宽度和动画减少模式。
- 只有实际观察到的模拟器或真机结果可以写入 `design-qa.md`。

## 13. 非目标

- 不实现实体牌拍照识别。
- 不新增第三套不完整主题。
- 不接入网络 AI、小艺、社区、商城或资讯。
- 不把参考截图作为整页背景，不把图鉴整张作为牌库运行时资源。

## 14. 自审结果

- 两套主题名称、来源和重复文件处理已经明确。
- 五步流程、四种牌阵、导航和本地追问没有冲突。
- “100% 还原”与响应式、无障碍及原生 ArkUI 的边界已经明确。
- 资源完整性失败时的行为明确为隐藏该主题，不会暴露半成品主题。
